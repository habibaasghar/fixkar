## 4. Canonical / metadata coverage gap

Explicit `alternates: { canonical }` is set on exactly **2 of 15+ route types**: `/[city]/page.tsx` and `/[city]/[category]/page.tsx`. Every static marketing page (`/about`, `/contact`, `/faq`, `/how-it-works`, `/partner`, `/partner/register`, `/privacy`, `/terms`, `/thank-you`, `/trust-safety`, `/services`, `/blog`, `/blog/[slug]`) exports `title`/`description` but **no explicit canonical tag**. `metadataBase` is set in `app/layout.tsx`, which helps resolve relative OG/Twitter image URLs, but does not by itself emit a `<link rel="canonical">` — that requires the explicit `alternates.canonical` field per page. Low risk today (no duplicate-URL variants exist for these single-instance pages), but worth closing before this becomes 40+ money pages relying on correct canonicalization.

## 5. Notable findings surfaced by this audit (not requested as a section here, but relevant to every row above — full discussion in the roadmap's "Current problems")

1. **`vendors.csv` shows zero confirmed-contacted vendors** for AC/Electrician/Plumbing/Cleaning, and **zero vendor rows at all for Painter** — yet all 5 render as fully "active, bookable" pages in Lahore.
2. **`/blog/[slug]` accepts any arbitrary slug and returns 200 with generic duplicate body content** — a real crawlability/duplicate-content liability, independent of the money-page work.
3. **Footer's "Popular Areas in Lahore" links (DHA, Gulberg, etc.) all point to the same URL** (`/lahore/ac-repair`) regardless of which area is clicked — internal-linking defect, wastes anchor-text opportunity, and is technically slightly misleading (an "Iqbal Town Lahore" link that goes to a generic AC repair page). Not in scope to fix this phase (Rule 2) but flagged for Phase 2.
4. Category slugs mix naming conventions (`electrician`, `painter` = person-nouns; `plumbing`, `cleaning` = activity-nouns; `ac-repair` = compound). Cosmetic inconsistency, not worth a redirect-churn fix now — noted for awareness only.
